# moon-wit — MoonBit WIT Bindgen

**A Wasm Component Model interface binding generator for MoonBit.**

- GitHub repository: <https://github.com/pei0331/moonbit-toml> (project renamed in-place to `moon-wit`)
- Author: pei0331

## 1. Abstract

`moon-wit` is a binding generator for the
[Wasm Component Model](https://component-model.bytecodealliance.org/) targeted
at [MoonBit](https://www.moonbitlang.com). It reads a WIT
(WebAssembly Interface Types) 1.0 document, parses its `interface` / `world` /
`resource` / `record` / `variant` definitions into an AST, and generates
type-safe MoonBit import/export bindings.

The primary deliverable is a CLI tool, `moon-wit`: feed it a `.wit` file and it
emits a MoonBit package that compiles with `moon build` out of the box.
It is the missing interoperability layer for Wasm Components in MoonBit —
infrastructure that any future Component-Model project can build on, rather
than a runtime library.

## 2. Why this direction

MoonBit's Wasm story currently stops at hand-written function exports and
basic WASI preview1. The Component Model and WIT are the next-generation
interoperability standard, explicitly on the official toolchain roadmap, yet
no public WIT parser or bindgen exists in the MoonBit community.

Building a developer tool avoids overlap with the runtime libraries on
mooncakes, and the acceptance criteria are objective: the WIT specification
and its test suite are public and maintained by the Bytecode Alliance, so
"does it parse and generate correctly" is measurable rather than subjective.

## 3. Originality and AI-use disclosure

- **Original implementation.** The WIT lexer, parser and code generator are
  written from scratch. They are *inspired by* `bytecodealliance/wit-bindgen`
  (Rust) and `wasm-tools-go` (Go), which is noted in the source comments;
  no code is ported.
- **AI use boundary.** AI is used only to assist with test cases and doc
  polish. The parser and code-generation templates are hand-written to avoid
  spec drift from AI hallucination.
- **Scope control.** The first release covers a core WIT 1.0 subset
  (`interface` / `world` / `resource` / `record` / `variant` / `func`), sized
  to be deliverable within the sprint.
- **License.** Apache-2.0. See [LICENSE](../LICENSE).

## 4. What was built (P0)

- **Lexer** (`lexer.mbt`) — tokens with 1-based line/column positions,
  comments and `@version` support.
- **Parser** (`parser.mbt`) — recursive-descent parser for the core subset,
  including named results and inline `interface` blocks in worlds.
- **AST** (`ast.mbt`) — full syntax tree with a WIT round-trip renderer.
- **Code generator** (`codegen.mbt`) — maps WIT definitions to idiomatic
  MoonBit (see [GRAMMAR.md](GRAMMAR.md) for the mapping tables). Emits
  `abort`-stub function bodies so generated packages always compile.
- **CLI** (`cmd/moon-wit`) — `parse`, `gen`, `version`, `help` subcommands
  with file I/O via the MoonBit runtime FFI.
- **Tests** — 26 tests covering the lexer, parser (AST shape and exact error
  positions) and codegen (generated declarations, type mapping, list-import
  detection).
- **Checked-in example** (`examples/hello`) — bindings generated by the CLI,
  compiled by CI via `moon build`.

**P0 checkpoint met:** `moon-wit parse tests/hello-world.wit` parses the
official hello-world-style WIT correctly.
**P1 checkpoint met:** the generated `examples/hello` bindings compile with
`moon build`.
